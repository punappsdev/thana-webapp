# คู่มือตั้งค่าแจ้งเตือนใบเสนอราคาเข้ากลุ่มไลน์

เมื่อลูกค้ากดขอใบเสนอราคาจากหน้า `/quote` ระบบจะส่งการ์ดสรุปคำขอเข้ากลุ่มไลน์ของทีม Sale **ตามสาขาที่ลูกค้าเลือก** โดยอัตโนมัติ ผ่าน LINE Messaging API

เอกสารนี้คือขั้นตอนตั้งค่าตั้งแต่ศูนย์ ใช้เวลาประมาณ 20–30 นาที

> หน้าจอของ LINE Developers Console กับ LINE Official Account Manager ถูกปรับบ่อย ชื่อเมนูอาจต่างจากที่เขียนเล็กน้อย แต่ตำแหน่งการตั้งค่ายังอยู่ที่เดิม

---

## ภาพรวม

| สิ่งที่ต้องเตรียม | ได้มาจาก |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developers Console → แท็บ Messaging API |
| `LINE_CHANNEL_SECRET` | LINE Developers Console → แท็บ Basic settings |
| `LINE_GROUP_ID_HEADQUARTERS` | log ของแอป ตอนเชิญบอทเข้ากลุ่มสำนักงานใหญ่ |
| `LINE_GROUP_ID_THALANG` | log ของแอป ตอนเชิญบอทเข้ากลุ่มถลาง |

ทั้งสี่ค่าเป็น **ตัวเลือก** — ถ้าไม่ตั้ง เว็บยังรับคำขอใบเสนอราคาได้ตามปกติ เพียงแต่ไม่ส่งแจ้งเตือนและขึ้นคำเตือนใน log เท่านั้น

---

## 1. สร้าง LINE Official Account (ตัวบอท)

บอทของ Messaging API คือ LINE Official Account หนึ่งบัญชี ไม่ใช่บัญชี LINE ส่วนตัว

1. เข้า <https://manager.line.biz> แล้วล็อกอินด้วย LINE Business ID (ใช้บัญชี LINE ของบริษัทล็อกอินได้เลย)
2. กด **สร้างบัญชีใหม่** แล้วกรอก
   - **ชื่อบัญชี** — ชื่อนี้จะแสดงในกลุ่มตอนบอทส่งข้อความ แนะนำให้สื่อความ เช่น `Thana Glass - แจ้งเตือนใบเสนอราคา`
   - ประเภทธุรกิจ อีเมล และประเทศ (ไทย)
3. สร้างเสร็จจะได้ LINE ID รูปแบบ `@xxxxxxx`

> **แนะนำให้สร้างบัญชีใหม่แยก ไม่ใช้ `@thanaglass` หรือ `@thanathalang` ที่ใช้คุยกับลูกค้าอยู่แล้ว** เพราะขั้นตอนถัดไปต้องปิดข้อความตอบกลับอัตโนมัติทั้งหมด ซึ่งจะกระทบการคุยกับลูกค้าถ้าใช้บัญชีเดิม

---

## 2. เปิด Messaging API

ที่ LINE Official Account Manager → **ตั้งค่า** (มุมขวาบน) → **Messaging API** → **เปิดใช้ Messaging API**

- ระบบจะให้เลือก **Provider** ถ้ายังไม่มีให้สร้างใหม่โดยใช้ชื่อบริษัท เช่น `Thana Glass`
- ยืนยันแล้วจะได้ **Channel ID** และ **Channel secret**

หลังจากนี้ channel จะไปปรากฏใน <https://developers.line.biz/console/> ด้วย

---

## 3. ตั้งค่าใน LINE Official Account Manager

ขั้นตอนนี้สำคัญที่สุด ห้ามข้าม

### 3.1 อนุญาตให้บอทเข้ากลุ่ม

**ตั้งค่า → ตั้งค่าบัญชี** → เปิด **"อนุญาตให้เข้าร่วมกลุ่มแชทและห้องแชท"**

ถ้าไม่เปิดข้อนี้ บอทจะ **ไม่ปรากฏในรายชื่อตอนเชิญเข้ากลุ่ม** เป็นจุดที่ติดกันบ่อยที่สุด

### 3.2 ปิดการตอบกลับอัตโนมัติ

**ตั้งค่า → การตอบกลับ**

| หัวข้อ | ตั้งเป็น | ถ้าตั้งผิด |
| --- | --- | --- |
| Webhook | **เปิด** | **ระบบพัง** — ปุ่ม Verify ไม่ผ่านและหา Group ID ไม่ได้ |
| ข้อความทักทายเพื่อนใหม่ | **ปิด** | แค่รก ระบบยังทำงาน |
| การตอบกลับอัตโนมัติ | **ปิด** | แค่รก ระบบยังทำงาน |
| แชท | เปิดหรือปิดก็ได้ | ไม่มีผล |

> **ถ้าหาหัวข้อ "โหมดการตอบกลับ" (Chat / Bot) ไม่เจอ ถือว่าปกติ** LINE ยกเลิกตัวเลือกนี้ไปแล้ว ของเดิมบังคับให้เลือกอย่างใดอย่างหนึ่งและโหมด Chat จะบล็อก webhook ปัจจุบันเปลี่ยนเป็นสวิตช์แยกอิสระที่เปิดพร้อมกันได้ จึงเหลือแค่ต้องเปิด **Webhook** ตัวเดียว
>
> ถ้าไม่เห็นสวิตช์ **Webhook** เลย แปลว่ายังไม่ได้เปิด Messaging API ให้กลับไปทำขั้นตอนที่ 2 ก่อนแล้ว refresh หน้า

สองข้อกลางปิดทีหลังได้ตลอด ไม่กระทบการแจ้งเตือน แต่ควรปิดตั้งแต่แรกเพราะ

- **ข้อความทักทาย** จะถูกโพสต์ลงกลุ่มตอนบอทเข้ากลุ่ม เป็นข้อความการตลาดสำเร็จรูปของ LINE ที่ดูไม่เข้ากับกลุ่มทำงานภายใน (ถ้าเผลอปล่อยไว้ ลบข้อความนั้นทิ้งได้เลย ไม่ต้องเชิญบอทเข้าใหม่) บาง console มีตัวเลือกให้ทักทายสมาชิกใหม่ที่เข้ากลุ่มด้วย ถ้าเจอก็ปิดไปพร้อมกัน
- **การตอบกลับอัตโนมัติ** จะทำให้บอทเด้งตอบข้อความที่ทีมงานคุยกันในกลุ่ม ปัญหาจริงคือทีมงานจะแยกไม่ออกว่าข้อความไหนคือการแจ้งเตือนใบเสนอราคาจริง เสี่ยงมองข้ามคำขอของลูกค้า

## 4. คัดลอก Token กับ Secret

เข้า <https://developers.line.biz/console/> → เลือก Provider → เลือก channel ที่เพิ่งสร้าง

- **แท็บ Basic settings** → เลื่อนลงหา **Channel secret** → คัดลอกไปใส่ `LINE_CHANNEL_SECRET`
- **แท็บ Messaging API** → เลื่อนลงล่างสุด **Channel access token (long-lived)** → กด **Issue** → คัดลอกไปใส่ `LINE_CHANNEL_ACCESS_TOKEN`

> Token จะแสดงเต็มเพียงครั้งเดียว เก็บไว้ให้ดี ถ้าหายต้องกด **Reissue** ใหม่ ซึ่งจะทำให้ token เดิมใช้ไม่ได้ทันที

---

## 5. ตั้ง Webhook URL

แท็บ **Messaging API** → หัวข้อ **Webhook settings**

1. **Webhook URL** = `https://<โดเมนของคุณ>/api/line/webhook`
2. เปิดสวิตช์ **Use webhook**
3. กด **Verify** ต้องขึ้น **Success**

ต้องใส่ `LINE_CHANNEL_SECRET` ลง `.env` และ restart แอปก่อนกด Verify ไม่งั้นจะได้ HTTP 503 (แอปตั้งใจตอบแบบนั้นเพื่อบอกว่ายังไม่ได้ตั้งค่า)

### ทดสอบบนเครื่อง dev

LINE ต้องยิงเข้า HTTPS ที่เข้าถึงได้จากอินเทอร์เน็ต ใช้ ngrok ช่วย

```bash
npm run dev
# เปิดอีกหน้าต่าง
ngrok http 3000
```

แล้วใช้ `https://xxxx.ngrok-free.app/api/line/webhook` เป็น Webhook URL — `next.config.ts` ตั้ง `allowedDevOrigins` รองรับ ngrok ไว้แล้ว

## 6. เชิญบอทเข้ากลุ่มและหา Group ID

แอป LINE **ไม่แสดง Group ID ที่ไหนเลย** วิธีเดียวที่จะได้มาคือดักจาก webhook ซึ่งเป็นเหตุผลเดียวที่ endpoint `/api/line/webhook` มีอยู่

1. ที่หน้าแรกของ LINE Official Account Manager จะมี QR code และ LINE ID ของบอท
2. ให้พนักงานคนหนึ่ง **เพิ่มบอทเป็นเพื่อน** ก่อน
3. เปิด **กลุ่ม Sale สำนักงานใหญ่** → เมนู → **เชิญ** → เลือกบอทจากรายชื่อเพื่อน
4. ดู log ของแอป จะขึ้นบรรทัดนี้ทันที

   ```
   [line webhook] event=join source=group groupId=Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx roomId=- userId=-
   ```

5. คัดลอกค่าหลัง `groupId=` ไปใส่ `LINE_GROUP_ID_HEADQUARTERS`
6. ทำซ้ำกับ **กลุ่ม Sale สาขาถลาง** เพื่อให้ได้ `LINE_GROUP_ID_THALANG`

**ดู log ได้ที่**

- เครื่อง dev — หน้าต่างที่รัน `npm run dev`
- VPS — ตาม process manager ที่ใช้ เช่น `pm2 logs` หรือ `journalctl -u <ชื่อ service> -f`

ถ้าพลาดจังหวะตอนเชิญเข้ากลุ่มไปแล้ว ให้พิมพ์ข้อความอะไรก็ได้ในกลุ่มหนึ่งครั้ง จะได้ event `message` พร้อม `groupId` เดิม

---

## 7. ใส่ค่าลง .env แล้ว restart

```env
LINE_CHANNEL_ACCESS_TOKEN=xxxxxxxxxxxxxxxxxxxxxxxxx
LINE_CHANNEL_SECRET=xxxxxxxxxxxxxxxxxxxxxxxx
LINE_GROUP_ID_HEADQUARTERS=Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
LINE_GROUP_ID_THALANG=Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

ไม่ต้องใส่เครื่องหมายคำพูด และต้อง **restart แอป** เพราะ Node อ่าน environment ตอนบูตเท่านั้น

สาขาที่ยังไม่ได้ตั้ง `LINE_GROUP_ID_*` จะถูกข้ามเฉพาะสาขานั้น สาขาที่เหลือยังส่งได้ตามปกติ

## 8. ทดสอบให้ครบวง

1. เปิด `/th/quote` ใส่สินค้าลงตะกร้า เลือก **สาขาถลาง** แล้วส่งฟอร์ม
2. การ์ดต้องเด้งเข้า **กลุ่มถลางเท่านั้น** ไม่ใช่กลุ่มสำนักงานใหญ่
3. เปิด `/admin/quotations/<id>` การ์ด **"แจ้งเตือนกลุ่มไลน์สาขา"** ต้องขึ้นป้าย **"ส่งเข้ากลุ่มแล้ว"** พร้อมเวลา
4. ส่งอีกใบโดยเลือก **สำนักงานใหญ่** เพื่อยืนยันว่าแยกกลุ่มถูกต้อง
5. ลองใส่สินค้าเกิน 30 รายการแล้วส่ง การ์ดจะถูกแบ่งเป็นหลายใบเลื่อนดูได้ และเลขรายการต้องเดินต่อเนื่องจนครบ

## เมื่อส่งไม่สำเร็จ

การแจ้งเตือนเป็นงานเสริมที่ล้มเหลวได้โดยไม่ทำให้คำขอของลูกค้าเสีย ลูกค้าจะยังเห็นหน้าสำเร็จพร้อมรหัสอ้างอิงเสมอ

- หน้า `/admin/quotations/<id>` จะขึ้นป้ายแดง **"ส่งไม่สำเร็จ"** พร้อมสาเหตุจริงจาก LINE
- หน้ารายการใบเสนอราคาจะขึ้นไอคอนเตือนหน้ารหัสอ้างอิงของใบที่ส่งไม่ผ่าน
- แก้ปัญหาแล้วกดปุ่ม **"ส่งแจ้งเตือนซ้ำ"** ได้ทันที ไม่ต้องให้ลูกค้าส่งคำขอใหม่

| อาการ | สาเหตุที่พบบ่อย |
| --- | --- |
| `LINE ตอบกลับ 401` | token ผิดหรือถูก reissue ไปแล้ว |
| `LINE ตอบกลับ 403` | บอทถูกเตะออกจากกลุ่ม หรือ Group ID ผิด |
| `LINE ตอบกลับ 429` | ใช้โควตาข้อความรายเดือนหมด |
| `ยังไม่ได้ตั้งค่า LINE_GROUP_ID_...` | ยังไม่ได้ใส่ Group ID ของสาขานั้น หรือใส่แล้วยังไม่ restart |
| กด Verify webhook ได้ 503 | ยังไม่ได้ใส่ `LINE_CHANNEL_SECRET` หรือยังไม่ restart |

## ข้อควรรู้

**โควตาข้อความ** — push message นับโควตารายเดือนของ LINE Official Account ตามจำนวนผู้รับ ไม่ได้นับเป็นหนึ่งข้อความต่อหนึ่งกลุ่ม กลุ่มที่มีสมาชิกมากจะกินโควตาเร็ว และคำขอที่มีรายการเยอะจนการ์ดถูกแบ่งเป็นหลายข้อความก็นับแยกกัน ควรตรวจสอบโควตาของแพ็กเกจที่ใช้อยู่ ถ้าปริมาณคำขอสูงอาจต้องอัปเกรดแพ็กเกจ

**Webhook หลังตั้งค่าเสร็จ** — การส่งแจ้งเตือนไม่ได้ใช้ webhook เลย จะปิดก็ได้ แต่แนะนำให้เปิดค้างไว้ เผื่อวันหลังเพิ่มกลุ่มหรือย้ายกลุ่มจะได้หา Group ID ใหม่ได้ทันที endpoint นี้เพียงแค่เขียน log ไม่บันทึกฐานข้อมูลและไม่ตอบข้อความใด ๆ

**อย่าเตะบอทออกจากกลุ่ม** — ถ้าบอทถูกเตะ การส่งจะพังทันที (LINE ตอบ 403) และถ้าเชิญกลับเข้ามาใหม่ Group ID จะยังเป็นค่าเดิม ไม่ต้องแก้ `.env`

**ความปลอดภัย** — `.env` อยู่ใน `.gitignore` แล้ว อย่า commit token เข้า repo ถ้า token หลุดให้กด Reissue ใน console ทันที
